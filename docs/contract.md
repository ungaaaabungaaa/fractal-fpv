# Fractal and virtual-camera contract, version 1

The shared C++17 header is `Source/FractalFPV/FractalCore/FractalCore.h`. It contains no Unreal include, subprocess, network, filesystem, or third-party dependency. Geometry/camera operations return a result/error instead of throwing for invalid caller input. Conversion helpers accept unmodified generated mesh data; arbitrary external meshes are not accepted by the application. Geometry generation accepts integer depth 0–3 and finite side length 1–100 metres. The canonical grid has 3^depth cells per axis; a cell survives when no base-three digit level has two or more centre digits. This retains 20^depth cells, at most 8,000, in a grid of at most 19,683 cells.

The mesh is centred on the origin with coordinates in [-side/2, side/2]. Emit only faces next to empty/outside cells. Each face has four vertices, outward axis-aligned unit normals, UVs and two indexed triangles. Core winding has cross(B−A,C−A) aligned with the outward normal. Output is bounded by 48,000 faces / 192,000 vertices / 288,000 indices before culling, derived from 8,000 cells × 6 faces. Report retained cells, exposed faces, triangles, naive unculled-cube triangles, area and volume. Do not claim manifold fabrication geometry or measured renderer speed.

Index-order conversion can reverse each triangle without changing vertices or normals. Metre-to-centimetre conversion multiplies positions by 100 only. The Unreal adapter compares the first triangle/normal of Epic's native unit box once and chooses the matching order; degenerate or malformed samples fail clearly. Browser WebGL uses a left-handed view/projection to preserve X-forward, Y-right, Z-up poses, and explicitly selects clockwise screen front faces. Engine appearance is unverified without an engine run.

Camera state has position in metres, yaw/pitch in degrees, and speed 0.1–100 m/s. Position components must remain within ±10,000 m, yaw within ±180°, pitch within ±89°. Look deltas are finite within ±180° per call and normalise yaw/clamp pitch. Movement controls forward/right/up and yaw/pitch rate are finite within [-1,1]; timestep is finite 0–0.1 seconds. Turn rate is 90 degrees/second at full input. Forward follows yaw/pitch, right follows yaw, and vertical is world Z. Normalise the combined world movement vector when its length exceeds 1, so diagonals cannot increase speed. Invalid requests leave state unchanged with an error. Translation at constant orientation is time-scaled; turning uses bounded explicit per-step integration. Collision, inertia, drone physics and hardware are absent.

The public Python-standard-library CLI supports `mesh --depth N --size-m M --out NEW_DIR`, `track --out NEW_DIR`, and `--help`. It calls the locally compiled C++ exporter, which emits JSON/OBJ/report/track data to stdout and performs no file writes. The wrapper owns bounded, exclusive new-directory output. All options are explicit/strict, numeric text must be consumed completely, and new output directories must have an existing parent. Refuse overwrite. Mesh bundles contain mesh.json, mesh.obj and report.json; track bundles contain camera-track.json. The compiled tool records its header SHA-256; the wrapper rejects stale tools that do not match the current shared source. JSON/OBJ exports round floating values to six decimal places for stable portable artifacts; full-precision numerical tests remain separate. Exports have finite values, fixed schema/version/unit metadata, no machine-specific paths, and no hidden engine dependency. Limit each tool output to 16 MiB. CLI exit codes: 0 success, 2 invalid input, 1 I/O/runtime failure.

The browser reads only committed bounded mesh/track fixtures. It offers mesh-depth selection, orbit/zoom controls, and playback of the actual portable-core track. It must label browser output separately from pending Unreal validation. No assets are fetched from a CDN and no analytics or device control is present. Its development server is loopback-only with a fixed public allowlist and no write interface.

The Unreal project uses the same header for mesh generation and camera movement. Its default Entry-map startup spawns the mesh, outside camera, dynamic lighting and a built-in material. Project files, module/targets, actor/pawn/game mode, input mappings and controls are supplied. The engine is not installed here. Unreal compilation, startup, rendering, input acceptance, profiling and packaged-game checks remain explicitly pending. Do not install the engine or accept an Epic agreement as part of this task.
